# AirIQ: 3-minute demo script

For whoever presents AirIQ live. Every step uses live data, so the exact numbers will differ from the ones quoted here (taken on 11 Nov 2026).

## Demo cities

| Role | City | Link | Why it is reliable |
| --- | --- | --- | --- |
| Polluted | Delhi, India | `/city/delhi-28.652-77.231` | Usually "Unhealthy" or worse in winter (US AQI 206 on 11 Nov). Dense WAQI station coverage on the map. |
| Clean | Wellington, New Zealand | `/city/wellington--41.287-174.776` | Usually "Good" (US AQI 20). Also UTC+13 in NZ summer, so local times are visibly different. |
| Unusual UTC offset | Kathmandu, Nepal | `/city/kathmandu-27.702-85.321` | UTC+05:45. Every time shown is the city's own local time, not the viewer's. |
| Ambiguous name | Springfield (search or assistant) | n/a | Three large US Springfields (Missouri, Illinois, Massachusetts). Search lists them with region and country. The assistant asks which one instead of guessing. |

London is a second ambiguous example: the search shows London, England first and London, Ontario second.

## Script (about 3 minutes)

**0:00 Dashboard** (`/`)
- *Say:* "AirIQ shows live air quality for any place on Earth, from public data: Open-Meteo and the Copernicus CAMS model, plus real ground stations."
- *Point at* the six popular-city cards. Each has a live AQI, a category colour **and** a pattern, so colour is never the only cue.
- *Click* the header toggle **US AQI → EU AQI** and back. "Both official scales, applied everywhere."

**0:20 City dashboard**: type `Delhi` in the search box, press ↓ and Enter.
- *Point at* the gauge, the plain-English verdict, "Updated X min ago" and the six pollutant cards with their WHO guideline ratio.
- *Point at* the cigarette card: "Roughly N cigarettes' worth of PM2.5 in the last 24 hours (Berkeley Earth rule of thumb, an approximation)."

**0:45 Forecast tab**: click **Forecast**.
- *Say:* "The official 5-day CAMS forecast, and our own transparent trend model for 48 hours, with its 80% range. It is backtested live against two simple baselines, and it says plainly when it doesn't win."
- *Point at* the "Best time outside" windows.

**1:05 History tab**: click **History**, then **30 days**.
- *Point at* the calendar heatmap and the weekday × hour heatmap. "Insights only appear when the numbers support them."

**1:20 Health tab**: click **Health** and switch the profile to **Asthma / respiratory condition**.
- *Say:* "Advice comes from a fixed rules table based on EPA, EEA and WHO guidance, never generated by AI, with its source on every line. General information, not medical advice."

**1:35 Map**: click **Map** in the header.
- *Point at* the heatmap (modelled CAMS grid) and the round station markers (measured, WAQI).
- *Click* **PM2.5**, then a marker → popup → "Open dashboard".

**1:55 Assistant**: open **Ask AirIQ** on the Delhi page (or `/assistant`).
- *Click* the quick prompt **"Is it safe to run outdoors today?"**. Point at the tool chips and the **Data used** panel. "Every number is checked against the data the tools fetched."
- *Type* `What's the air like in Springfield?`. It asks which Springfield.

**2:25 Alerts**: click **Create alert** on the city page (or `/alerts`).
- Leave the defaults and click **Save alert**, then **Check now**. "Alerts run while AirIQ is open, with quiet hours and browser notifications on request."

**2:40 Compare, share, offline (pick one if time is short)**
- `/compare?cities=delhi-28.652-77.231,wellington--41.287-174.776,kathmandu-27.702-85.321`: side-by-side cards, ranking and overlay charts.
- On a city page, click **Report**, then **Download PDF**.
- Offline (only if the production build is running): open DevTools → Network → Offline and reload. The page loads, labelled "Offline: showing data from HH:MM, not live". Go back online and a "Back online" toast appears.

**3:00 Close** with the **About** link in the footer: sources, licences, methods and limitations.

## If an API is slow or rate-limited

- **Open-Meteo slow or failing:** each panel shows its own error with **Retry**; nothing is filled in. Server responses are cached for 10–30 minutes, so cities you warmed up beforehand keep working.
- **Open-Meteo 429 (rate limit):** the free API allows under 600 calls a minute and 10,000 a day. A demo uses a few dozen. If you hit it, switch to a warmed-up city and say why.
- **WAQI stations missing:** the map still shows the CAMS grid and heatmap; the legend says stations are unavailable.
- **Gemini quota (429):** the free tier allows about 20 requests per day per model, and one question uses 1–4. The app retries once on the backup model (`gemini-3.5-flash-lite`) and shows "Answered by backup model". If both are exhausted it says the usage limit was reached. Switch `GEMINI_MODEL` or skip the assistant step.
- **No network at all:** run the production build and use the offline flow above. Pages opened earlier load with labelled data.

## Pre-demo checklist

- [ ] `.env.local` has `GEMINI_API_KEY` and `WAQI_TOKEN`. Check `/about` → "Features on this server" (all **On**).
- [ ] Gemini quota left: ask one question in `/assistant` about 15 minutes before. If it says the limit is reached, set `GEMINI_MODEL=gemini-3.5-flash-lite` and restart.
- [ ] Run the production build (`npm run build && npm start`), not `npm run dev`. It is faster, and the service worker and offline mode only run in production.
- [ ] Warm the caches: open each demo city once (Delhi, Wellington, Kathmandu), its Forecast and History tabs, `/map` around Delhi, and the compare link above.
- [ ] Check the network: open `/map` and confirm the basemap tiles load (they come from Esri, not our server).
- [ ] Browser zoom 100%, a clean profile (no other extensions), and notifications allowed if you show alerts.
- [ ] Close other AirIQ tabs, so alerts don't fire twice during the demo.
